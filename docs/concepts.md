# MDRAP Core Concepts & Architecture

This document specifies the core data models, lifecycle states, bitmask representations, and lineage guarantees implemented across the Market Data Reliability & Acceleration Platform (MDRAP).

---

## 1. Quality Statuses & Precedence

Every market event processed by MDRAP is assigned one of three deterministic quality states defined in `mdrap.models.QualityStatus`:

| Status | Value | Severity | Operational Action | Downstream Treatment |
| :--- | :--- | :--- | :--- | :--- |
| **VALID** | `1` | Lowest | Normal event passing all structural and statistical rules. | Dispatched to trading desks, analytics, and primary projection. |
| **SUSPICIOUS** | `2` | Intermediate | Event exhibits market anomalies (e.g. wide spread, volatility spike, or cross-feed divergence) that may represent real market events rather than corrupted data. | Dispatched with warning flags and attached `Reason` codes. Downstream consumers may filter or shadow. |
| **INVALID** | `3` | Highest | Event violates hard protocol boundaries, schema constraints, or cryptographic integrity (e.g. NaN/Inf prices, negative quantities, crossed quotes). | **Quarantined immediately.** Excluded from BBO calculation and primary order book state. |

### Strict Non-Downgradable Priority
Quality status transitions follow a strict lattice:
$$\text{INVALID} > \text{SUSPICIOUS} > \text{VALID}$$

Once an event is marked `INVALID` by any validation stage (gateway, native C kernel, or quality engine), subsequent stages **cannot** downgrade it to `SUSPICIOUS` or `VALID`. Similarly, a `SUSPICIOUS` event cannot be downgraded to `VALID`.

## 2. Reason Codes & Bitmask Allocations

MDRAP defines canonical quality rules using a single-source X-Macro (`src/mdrap/rules.def`). The 64-bit integer mask (`quality_flags`) is partitioned into three discrete ranges:

| Bit Range | Allocation | Description |
| :--- | :--- | :--- |
| **Bits 0 – 15** | Core Platform Rules | 15 built-in deterministic validation checks evaluated in both native C (`fastpath.c`) and pure Python (`quality.py`). |
| **Bits 16 – 31** | Core Platform Reserved | Reserved for future engine-level checks. |
| **Bits 32 – 63** | Custom & Venue Rules | User-registered custom anomaly checks and third-party venue validators. |

### Core Rule Catalog (Bits 0–14)

| Bit | Hex Mask | Reason Code | Severity | Description |
| :---: | :---: | :--- | :--- | :--- |
| 0 | `0x0001` | `SCHEMA_VIOLATION` | INVALID | Payload missing required fields or non-numeric/NaN/Inf data types. |
| 1 | `0x0002` | `DUPLICATE` | INVALID | Duplicate sequence number or message ID already observed in session window. |
| 2 | `0x0004` | `SEQUENCE_GAP` | SUSPICIOUS | Missing sequence number indicating upstream packet drop. |
| 3 | `0x0008` | `OUT_OF_ORDER` | SUSPICIOUS | Decreasing sequence number or inverted timestamp sequence. |
| 4 | `0x0010` | `STALE` | SUSPICIOUS | Exchange timestamp exceeds maximum allowed staleness threshold relative to engine clock. |
| 5 | `0x0020` | `PRICE_ANOMALY` | SUSPICIOUS | Price movement exceeds statistical Welford volatility threshold ($k \times \sigma$). |
| 6 | `0x0040` | `CROSSED_QUOTE` | INVALID | Bid price is strictly greater than ask price ($P_{\text{bid}} > P_{\text{ask}}$). |
| 7 | `0x0080` | `CROSS_FEED_DISAGREEMENT` | SUSPICIOUS | Consensus divergence between redundant feeds exceeds arbitration tolerance. |
| 8 | `0x0100` | `MALFORMED` | INVALID | Malformed wire bytes, unparseable JSON/SBE framing, or corrupt payload. |
| 9 | `0x0200` | `CIRCUIT_FILTER_BREACH` | INVALID | Price exceeds daily exchange circuit limit bands (e.g. NSE/BSE $\pm 10\%$). |
| 10 | `0x0400` | `VOLATILITY_INTERRUPTION` | SUSPICIOUS | Price breaches dynamic corridor triggers (e.g. XETRA dynamic corridor $\pm 5\%$). |
| 11 | `0x0800` | `SPECIAL_QUOTE_INDICATION` | SUSPICIOUS | Special quote conditions (e.g. TSE Tokuhai quote indication $\pm 8\%$). |
| 12 | `0x1000` | `TS_IMPLAUSIBLE` | INVALID | Exchange timestamp is implausibly in the future relative to gateway ingress clock. |
| 13 | `0x2000` | `RATE_LIMITED` | SUSPICIOUS | Ingress rate limit exceeded for feed source. |
| 14 | `0x4000` | `SECURITY_REJECT` | INVALID | Authentication failure, HMAC mismatch, or payload sanitization rejection. |

## 3. The Canonical Event Model

Raw events from heterogeneous venues (Binance JSON, ITCH binary, FIX/FAST, REST) are normalized into the immutable `mdrap.models.CanonicalEvent` structure:

```python
@dataclass(slots=True)
class CanonicalEvent:
    event_id: str                      # Monotonic unique ID generated by engine
    instrument_id: str                 # Standardized ticker symbol (e.g. "AAPL", "BTC-USDT")
    event_type: EventType              # TRADE, QUOTE, BBO, BOOK, or DEPTH
    exchange_timestamp: float          # Venue exchange time (Unix seconds float)
    receive_timestamp: float           # Gateway ingress time (Unix seconds float)
    processing_timestamp: float = 0.0  # Quality evaluation time (Unix seconds float)
    source: str = ""                   # Originating feed identifier
    sequence_number: int | None = None # Source sequence (if provided by venue)
    price: float | None = None         # Trade execution price
    quantity: float | None = None      # Trade execution quantity
    bid_price: float | None = None     # Best bid price
    bid_size: float | None = None      # Best bid volume
    ask_price: float | None = None     # Best ask price
    ask_size: float | None = None      # Best ask volume
    quality_status: QualityStatus = QualityStatus.VALID
    reasons: list[str] = field(default_factory=list)
    raw_id: str = ""                   # Lineage pointer to raw ingress record
    source_id: int = -1                # Numeric source venue identifier
    instrument_id_int: int = -1        # Fastpath mapped symbol identifier
    session_id: str | None = None      # Ingestion session ID
```

### Memory & Performance Optimizations
- **`slots=True`**: Suppresses Python dynamic `__dict__` creation, reducing memory footprint to fixed descriptor offsets and eliminating pointer indirection.
- **Fixed-Point Scaling**: The native C kernel (`fastpath.c`) represents prices as 64-bit scaled integers (`int64_t` with default scale factor $10^8$) to eliminate IEEE 754 floating-point drift and non-deterministic rounding errors.

## 4. Lineage & Cryptographic Audit

Every canonical event maintains strict audit lineage tracing from raw wire bytes to downstream persistence:

1. **Raw Wire Capture**: Ingress raw payloads are assigned an immutable `raw_id`. The unparsed wire payload is logged to the write-ahead log (`IngestLog`).
2. **Provenance Link**: When `CanonicalEvent` is generated, `raw_id` is embedded directly into the record.
3. **Quarantine Retention**: Any event flagged as `INVALID` is copied to the `quarantine` store along with all attached `Reason` codes and full payload, ensuring zero silent discards.
4. **SHA-256 Merkle Chain**: As events commit into the persistent storage engine (`mdrap.storage.Store`), leaf hashes are computed:
   $$H_i = \text{SHA-256}(H_{i-1} \parallel \text{event\_id} \parallel \text{timestamp} \parallel \text{payload})$$
   Auditors verify the complete log integrity via `store.verify_audit_integrity()`.
