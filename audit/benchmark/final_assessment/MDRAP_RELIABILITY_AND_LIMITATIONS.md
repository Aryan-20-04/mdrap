### 1.3 Root Cause Analysis: Proven Facts vs. Plausible Explanation
1. **Proven Facts:**
   - The loss occurred exclusively during Minutes 6–8 of the soak.
   - The elapsed wall-clock time between Minute 5 and Minute 6 jumped from **T+300s to T+1309s** (a ~16.8-minute real-world gap during which only 31k events were processed).
   - TCP client reconnect count remained at **0** (`client.reconnect_count == 0`), proving the TCP connection never dropped or reset.
   - The background exporter persisted **5,733,615 lines** to disk, which matches `consumer_received: 5733615` with **zero queue drops** and **zero write errors**. The exporter was not the source of loss.
2. **Plausible Explanation:**
   - The host system (Windows 11 Enterprise desktop) entered sleep suspension or background power throttling. When the host resumed, the producer thread rapidly injected catch-up batches into the Windows TCP loopback socket. The socket receive buffer experienced three momentary overflows before the reader thread could drain the backlog.
3. **Integrity Mechanism Verdict:**
   - The platform's sequence gap tracking, XOR checksum, arithmetic sum accumulator, and rolling multiset hash immediately flagged the discrepancy (`reconciliation_verdict: "MISMATCH"`). The platform successfully prevented silent data corruption.

## 3. Mathematical Capabilities and Theoretical Limitations of Checksums

Stage C utilized four mathematical checksums: 64-bit XOR, 64-bit Sum, Min/Max sequence bounds, and a 64-bit rolling multiset polynomial hash.

> [!CAUTION]
> **Theoretical Limitations of Aggregate Hashes**:
> - **XOR Accumulators** detect any odd number of bit errors, but an even number of identical bit errors can cancel out.
> - **Arithmetic Sum Accumulators** detect single insertions or omissions, but equal and opposite substitutions ($x+k$ and $y-k$) cancel out.
> - **Multiset Polynomial Hashes** are collision-resistant under random distributions, but with 64 bits, birthday collisions occur at $\approx 2^{32} \approx 4.29 \times 10^9$ items.
> - **Audit Fact:** While the combination of all four checks provides high empirical confidence, **aggregate hash equivalence is not a formal mathematical proof of identical per-event ordering or uncorrupted multi-field payload state**. Absolute verification requires full transaction replay against persisted journals.

## 4. Comprehensive Known Limitations Register

### 4.1 String Epoch Lexicographical Reversal Limitation
- **Defect:** In `external_sidecar/mdrap_observer/observer/state.py`, `_compare_epochs()` attempts integer conversion. For alphanumeric strings, it falls back to Python string comparison.
- **Limitation:** `'session-2' > 'session-10'` because `'2' > '1'`. If an upstream venue emits unpadded session suffixes across double digits, `session-10` packets will be evaluated as `cmp < 0` (stale packets) and discarded from gap tracking.
- **Operational Requirement:** Feeds must strictly provide integer epochs, zero-padded strings (`session-02`), or ISO 8601 date prefixes (`2026-11-22:session-1`).

### 4.2 Recycled Identifiers Across Days
- Plain string identifiers reused on consecutive days without date prefixes (e.g. `session-1` on Day 2 vs `session-1` on Day 1) compare as equal (`0`) and cannot detect cross-day session resets.

### 4.3 Windows Loopback Socket Sensitivity
- Windows desktop network buffers are vulnerable to packet drops if the CPU undergoes aggressive power throttling or sleep states during high-rate loopback streaming.

### 4.4 Tail Latency Amplification
- While median latency is ~0.8–1.1 ms, the 99th percentile reaches **3.36–3.64 ms** due to Python GIL contention and socket dispatch, making standard TCP unsuitable for low-latency HFT execution.

### 4.5 Unverified Multi-Host Network Topologies
- All Stage C benchmarks were executed over localhost (`127.0.0.1`). Real-world network physical constraints (PTP hardware timestamps, NIC packet ring drops, WAN routing latency) remain unverified.

### 4.6 High-Cardinality Channel Scaling
- Observer in-memory state tracks sequences per `(gateway_id, symbol)` channel key. Tracking thousands of low-liquidity instruments requires tuning memory retention and LRU channel eviction policies.
