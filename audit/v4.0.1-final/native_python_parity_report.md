# MDRAP v4.0.1 — Native C & Pure Python Semantic Parity Report

## 1. Scope & Objective

Design Principle 4 explicitly dictates:
> **Pure Python Fallback Parity** — pure Python must match native C validation outputs exactly.
> Design Principle 10: **Quality status has strict priority**: INVALID > SUSPICIOUS > VALID. Never downgrade.

This report documents the verification of 100% semantic and operational parity between:
- **Tier 1**: Pure Python + stdlib baseline engine (`src/mdrap/quality.py`, `src/mdrap/engine.py`).
- **Tier 2**: Native C Hot Path Kernel (`src/fastpath.c`, `src/mdrap_core.c`, `src/mdrap/_fastpath_c.pyd`, `src/mdrap/_fastpath_native.dll`).

---

## 2. Shared Specification & Rule Synchronization

Rule parity is enforced using the single-source-of-truth definition file `rules.def`.
The code generation tool `tools/gen_reasons.py --check` runs as Release Gate Stage 3 to mathematically guarantee that:
1. Every rule constant in C (`RULE_*` in `src/fastpath.c`) corresponds to the identical bitmask and reason code in Python (`Reason` enum in `src/mdrap/models.py`).
2. The bitmask bit-index mapping is identical:
   - Bit 0: `STALE_TIMESTAMP`
   - Bit 1: `FUTURE_TIMESTAMP`
   - Bit 2: `NEGATIVE_OR_ZERO_PRICE`
   - Bit 3: `NEGATIVE_OR_ZERO_QUANTITY`
   - Bit 4: `CROSSED_SPREAD`
   - Bit 5: `WIDE_SPREAD`
   - Bit 6: `PRICE_SPIKE`
   - Bit 7: `OUT_OF_SEQUENCE`
   - Bit 8: `SESSION_CHANGE`
   - Bit 9: `CORRUPT_PAYLOAD`
   - Bit 10: `DUPLICATE_EVENT`
   - Bit 11: `VENUE_DISAGREEMENT`
   - Bit 12: `STALE_SEQUENCE`
   - Bit 13: `SEQUENCE_GAP`
   - Bit 14: `RATE_LIMIT_EXCEEDED`
3. Status priority logic (`INVALID > SUSPICIOUS > VALID`) is identical:
   - Any INVALID rule triggers `QualityStatus.INVALID`.
   - Any SUSPICIOUS rule (in the absence of INVALID) triggers `QualityStatus.SUSPICIOUS`.
   - Otherwise, `QualityStatus.VALID`.

## 4. Key Hardening in v4.0.1

1. **Feed Jump Limit Alignment**:
   In v4.0.0, the C accelerator defaulted `seq_jump_limit` to `1 << 24` (16,777,216) while Python defaulted to `50`. In v4.0.1, `FastQualityEngine` strictly synchronizes `seq_jump_limit` from configuration across both tiers, ensuring identical handling of exchange sequence restarts.
2. **Circular Buffer Sequence Width**:
   Native C and Python circular tracking arrays were upgraded to store 64-bit sequence numbers rather than 16-bit masked values, completely eliminating false duplicate collisions on sequence index reuse.
3. **Quarantine Payload Formatting**:
   Quarantine record schemas and JSON-encoded reason formats generated by the C hot path kernel match Python dataclasses field-for-field.
