# MDRAP Phase 3 — Canonical Event Contract

**Document Identifier**: `MDRAP-CONTRACT-P3-001`  
**Date**: October 9, 2026  
**Status**: NORMATIVE SPECIFICATION  

---

## 1. Event Model & Field Definitions

Every event processed by MDRAP conforms to the following schema:

| Field Name | Type | Precision / Bounds | Description |
|---|---|---|---|
| `event_id` | `uint64` / `str` | Monotonic uint64 | Unique identifier assigned by engine or WAL. |
| `instrument_id` | `str` (ASCII) | Max 32 chars | Canonical ticker / symbol (e.g. `AAPL`, `EUR/USD`). |
| `event_type` | `str` / `enum` | Max 16 chars | `TRADE`, `BBO`, `BOOK_UPDATE`, `HEARTBEAT`. |
| `source` | `str` (ASCII) | Max 16 chars | Venue identifier (e.g. `NASDAQ`, `CME`, `BINANCE`). |
| `feed_id` | `str` (ASCII) | Max 16 chars | Channel identifier (e.g. `MOLD64`, `WS_DIRECT`). |
| `sequence` | `uint64` | `[0, 2^64-1]` | Sequence number within `(source, feed_id, session_id)`. |
| `exchange_ts` | `int64` / `float`| Nanoseconds / sec | Timestamp generated by exchange matching engine. |
| `receive_ts` | `int64` / `float`| Nanoseconds / sec | Timestamp when MDRAP ingress received packet. |
| `price` | `float64` / `int64` | 8 decimals fixed | Trade execution price or reference price. |
| `size` | `float64` / `int64` | 4 decimals fixed | Executed quantity or order size. |
| `bid` | `float64` (opt) | 8 decimals fixed | Best bid price (for BBO / Quote). |
| `ask` | `float64` (opt) | 8 decimals fixed | Best ask price (for BBO / Quote). |
| `quality_flag` | `uint8` | `0=VALID, 1=SUSPICIOUS, 2=INVALID` | Quality engine verdict. |
| `reasons` | `list[str]` | Array of reason codes | Anomaly or quarantine explanations. |

---

## 2. Invariants & Guarantees

1. **Non-Negativity**: `price > 0.0` and `size >= 0.0` for all trades; non-positive prices trigger `INVALID` quality flag.
2. **Quote Ordering**: `bid <= ask` strictly. If `bid > ask`, event is flagged `INVALID` (crossed market).
3. **Sequence Monotonicity**: Any decrease in `sequence` for the same `(source, feed_id)` triggers `OUT_OF_ORDER` or `DUPLICATE` quarantine.
4. **Timestamp Ordering**: `receive_ts >= exchange_ts` under synchronized clocks; negative latency triggers clock-skew warning (`clock_source="GATEWAY_RECV"` fallback).
